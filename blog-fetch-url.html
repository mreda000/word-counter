Analyze Webpage Text and Troubleshoot URL Fetching

Published by ChickenTask · Updated November 21, 2026

The word counter can request a webpage and load its text into the editor. This is useful for checking a page you maintain or studying a passage you are permitted to use. It depends on the source website allowing a browser request, and the imported result may need cleaning before the numbers represent the passage you intended to measure.

Fetch a supported page

  1. Keep a copy of any draft currently in the editor. A successful import replaces the editor's contents.
  2. Open the Word Counter & Text Analyzer and enter a complete https:// webpage URL.
  3. Select Fetch & Analyze. The source needs to return a successful response with a supported text content type: HTML, plain text, or XHTML.
  4. Inspect the imported text. Remove menus, captions, related links, or other material that is not part of the passage you want to analyze.
  5. Check the results after cleaning. Use Copy results if you need to record the counts.

For HTML pages, the importer removes script, style, navigation, header, and footer elements, then uses the first matching main or article element, or the page body as a fallback. It simplifies whitespace into spaces. This means imported HTML usually loses its original paragraph breaks; the paragraph count does not reconstruct the page's visual layout.

Why a page may not load

The source blocks cross-origin requests

Your browser enforces rules called CORS. A page can open in its own tab but still refuse a script on ChickenTask permission to read it. ChickenTask cannot change the source server's permission settings. MDN explains how CORS works.

The URL points to a file or restricted page

A PDF, image, login screen, or error response may not provide the supported text you expected. Use the public article URL when one exists. The fetch feature does not bypass authentication or paywalls.

The article appears only after the page runs JavaScript

The importer reads the response HTML; it does not run that site's scripts to construct the article. A dynamically loaded page may therefore produce an empty or incomplete result.

The link or connection failed

A mistyped URL, unavailable site, HTTP error, or browser security restriction can also cause the general fetch-error message. That message alone does not prove that CORS is the cause.

Although the field accepts HTTP and HTTPS links, an insecure HTTP request from the HTTPS site may be blocked by the browser. Prefer the source's HTTPS address when available.

Use the copy-and-paste fallback

Open the source in its normal browser tab and select the passage you are allowed to use. Copy it, paste it into ChickenTask's editor, and compare the beginning and ending with the original. This avoids counting unrelated page elements and lets you preserve paragraph breaks.

For example, to measure only a recipe's introduction, do not include ingredient quantities, navigation labels, and reader comments unless they are part of your task. The counter measures everything left in the editor; it does not decide which text is relevant.

Keep permissions and privacy in mind

URL fetching sends a request from your browser to the source website, which can receive ordinary connection information. Pasted text is analyzed in the browser by the counter; that does not mean the entire site makes no network requests. See the Privacy Policy for advertising, analytics, and account information.

Being able to fetch or copy text does not grant permission to republish it. Keep the source link with your notes and use material in line with its terms and your permissions. For scanned text you own or are permitted to process, the separate Image to Text tool can help; proofread its output before counting.
